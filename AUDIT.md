# Thermo-Nuclear Code Audit — Findings

Multi-agent audit of the codebase (quality, maintainability, performance, modernization), following the `thermo-nuclear-code-quality-review` skill. Each finder's output was adversarially verified before landing here.

Format: `problem type - actual problem - file/files it touches`

## Findings

### Critical (6)

- **duplication** - The SCDW insurance pricing formula (calculateSCDW: base 2x daily rate, +6 then +5 per 3-day block) is copy-pasted in 4 files, and the copies are fed divergent daily rates: the reservation page charges seasonal price, additional-features-card displays base price with no seasonal multiplier, and edit-reservation-dialog uses seasonal in one path but base in another within the same file — so the SCDW price shown to the customer can differ from what is charged and from what admins recompute. Extract one canonical implementation into lib/vehicle-utils.ts (or a dedicated pricing module) with a defined rate input. - `app/[locale]/reservation/page.tsx`, `components/admin/reservations/edit-reservation-dialog.tsx`, `components/features/reservations/additional-features-card.tsx`, `hooks/use-reservation-pricing.ts`, `lib/vehicle-utils.ts`
- **file-size** - The reservation page is an 1888-line 'use client' God-component with 19 useState hooks owning localStorage persistence, the full pricing engine (computed twice: a display path and a divergent submit path), Zod validation, submission orchestration, and all card JSX; every keystroke re-renders the entire tree and re-executes the unmemoized calculateTotalPrice() in the render body. A decomposition (hooks/use-reservation-form.ts, use-reservation-pricing.ts, three card components) was started and abandoned — none of it is imported. Split into memoized child components with a single memoized pricing hook shared by summary UI and submit payload. - `app/[locale]/reservation/page.tsx`, `hooks/use-reservation-form.ts`, `hooks/use-reservation-pricing.ts`, `components/features/reservations/personal-info-card.tsx`, `components/features/reservations/payment-method-card.tsx`, `components/features/reservations/additional-features-card.tsx`
- **performance** - createReservation (reservations.ts:80-86) and createTransfer (transfers.ts:64-69) compute the next sequential booking number by .collect()-ing the ENTIRE table and reducing for the max on every single booking. Cost grows linearly with lifetime bookings, will hit Convex transaction read limits, and reading the whole table into the mutation's read set makes concurrent bookings OCC-conflict and retry, serializing the money path. Fix: a counter document, or an index on reservationNumber/transferNumber read via .withIndex().order('desc').first(). - `convex/reservations.ts`, `convex/transfers.ts`, `convex/schema.ts`
- **performance** - app/layout.tsx (root layout) calls `await headers()` to read x-pathname solely to compute <html lang>; a dynamic API in the root layout opts every route into per-request rendering, defeating generateStaticParams for home, /cars, /blog, and all car/blog detail pages, which hit Convex via fetchQuery on every request instead of being statically prerendered/ISR'd. Derive lang from the [locale] segment instead of headers(). - `app/layout.tsx`, `proxy.ts`, `app/[locale]/layout.tsx`, `app/[locale]/cars/[slug]/page.tsx`, `app/[locale]/blog/[slug]/page.tsx`
- **security** - Admin-only Convex write functions are public internet endpoints with zero auth checks: all vehicles, blogs, seasons, transferPricing, and vehicleClasses create/update/remove/reorder/upload mutations. Admin enforcement exists only in the Next.js Clerk middleware (proxy.ts), which direct calls to the Convex deployment bypass — anyone can call api.vehicles.remove or api.seasons.setCurrent. Add a shared requireAdmin(ctx) helper or an adminMutation wrapper to every admin write. - `convex/vehicles.ts`, `convex/blogs.ts`, `convex/seasons.ts`, `convex/transferPricing.ts`, `convex/vehicleClasses.ts`, `proxy.ts`
- **wrong-layer** - createReservation and createTransfer are public, unauthenticated mutations that trust client-supplied money fields (totalPrice, protectionCost, deductibleAmount, baseFare, distancePrice, seasonalMultiplier) and store them verbatim, even sending confirmation emails at the client-chosen price — any client can submit arbitrary totals. All pricing rules (warranty table, SCDW, `days * 3` extras, tier/seasonal math, location fees) live only in client code; server-side building blocks are query-only or missing. Move pricing into a pure shared module and recompute/validate totals inside the create mutations. - `convex/reservations.ts`, `convex/transfers.ts`, `convex/transferPricing.ts`, `convex/seasons.ts`, `app/[locale]/reservation/page.tsx`, `lib/vehicle-utils.ts`, `components/features/reservations/additional-features-card.tsx`

Convex caps function args at ~16MiB total / ~1MiB per byte value while the UI allows 10x10MB files, so realistic uploads fail outright. Also vehicles.uploadImages persists via the public unauthenticated api.vehicles.update instead of an internal mutation.
